Hi Joachim,

Here's a comprehensive summary of the experiment data analysis and our options.

--------------------------------------------------------------------------------
1. WHAT HAPPENED - THE RACE CONDITION
--------------------------------------------------------------------------------

We designed the experiment with 363 unique parameter combinations:
- 3 ps levels (0.2, 0.35, 0.5)  
- 11 d'_Human levels (0.5–2.5)
- 11 d'_DS levels (0.5–2.5)

The row assignment was supposed to work like this:
1. User lands → Select an unused CSV row (used=0)
2. Mark row as in-progress (used=0.5)
3. User completes → Mark row as used (used=1)

THE BUG: Steps 1 and 2 were NOT atomic. The code was:
   ```python
   events_data, csv_row_id, ps, dprime_h, dprime_s = load_block_trials()  # Step 1: SELECT row
   # ... other code ...
   mark_row_in_progress(csv_row_id)  # Step 2: MARK row (happens LATER)
   ```

When Prolific sent a burst of users simultaneously (which happens during study launch),
multiple users executed Step 1 at the SAME time, saw the SAME available rows,
and were assigned the SAME row BEFORE any could be marked as 0.5.

RESULT:
- 419 completed users (non-test)
- But only 294 unique combinations have data (some got 2-3 users)
- 69 combinations (19%) have NO completion data

--------------------------------------------------------------------------------
2. IS THE DATA BIASED?
--------------------------------------------------------------------------------

We ran statistical tests on the missing combinations:

| Factor     | χ² statistic | p-value | Result      |
|------------|--------------|---------|-------------|
| ps         | 4.26         | 0.119   | ✅ RANDOM   |
| d'_Human   | 6.72         | 0.751   | ✅ RANDOM   |
| d'_DS      | 6.72         | 0.751   | ✅ RANDOM   |

All p > 0.05 → The missing combinations are RANDOMLY distributed, not systematically biased.

Additionally, the mean/median of completed users match expected uniform distribution:
- d'_Human: Mean=1.486, Median=1.500 (expected: 1.5) ✅
- d'_DS: Mean=1.495, Median=1.500 (expected: 1.5) ✅
- ps: Mean=0.347, Median=0.350 (expected: 0.35) ✅

5. CODE FIX FOR FUTURE EXPERIMENTS
--------------------------------------------------------------------------------

The fix makes row selection ATOMIC by using database locking:

CURRENT CODE (BUGGY):
```python
# landing_page view:
events_data, csv_row_id, ps, dprime_h, dprime_s = load_block_trials()  # SELECT
# ... other code can execute here for other users ...
mark_row_in_progress(csv_row_id)  # MARK (too late!)
```

FIXED CODE (ATOMIC):
```python
from django.db import transaction
from filelock import FileLock

def load_block_trials_atomic() -> tuple:
    '''Atomic row selection using file lock'''
    csv_path = os.path.join(settings.BASE_DIR, "DATA", "conditions.csv")
    lock_path = csv_path + ".lock"

    with FileLock(lock_path):  # Only ONE process can hold this lock
        event_data = pd.read_csv(csv_path)

        # Select fresh row
        fresh_rows = event_data[event_data['used'] == 0]
        if len(fresh_rows) > 0:
            selected_row = fresh_rows.sample(n=1).iloc[0]
            row_id = int(selected_row['id'])

            # Mark as 0.5 IMMEDIATELY (still inside lock)
            event_data.loc[event_data['id'] == row_id, 'used'] = 0.5
            event_data.to_csv(csv_path, index=False)
        else:
            # Handle no fresh rows...
            pass

    # Lock is released here - other users can now read
    return data_dict, row_id, ps, dprime_h, dprime_s
```

ALTERNATIVE (Better): Move conditions to database:
```python
# models.py
class ExperimentCondition(models.Model):
    ps = models.FloatField()
    dprime_h = models.FloatField()
    dprime_s = models.FloatField()
    used = models.FloatField(default=0)  # 0, 0.5, 1
    # ... trial columns ...

# views.py
from django.db import transaction

def get_next_condition():
    with transaction.atomic():
        condition = ExperimentCondition.objects.select_for_update(
            skip_locked=True  # Skip rows being used by other transactions
        ).filter(used=0).first()

        if condition:
            condition.used = 0.5
            condition.save()

        return condition
```

This uses database-level locking which is much more reliable than file locks.
